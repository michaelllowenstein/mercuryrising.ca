FIG. 1 — System architecture
Data flow from a tenant domain specification through the adapter synthesis engine to four target runtimes. The CLI, the portal, and the API each consume one or more generated artifacts. Solid arrows represent generated artifacts; dashed arrows represent runtime calls.
FIG. 2 — Tenant isolation model
Multiple independent tenant domain specifications each validate against a shared JSON Schema. The schema, synthesis engine, analysis engine, API, and portal are shared tenant-agnostic components. Tenant context enters each component exactly once, at its configuration boundary.
FIG. 3 — Adapter synthesis flow
Input domain.json flows through schema validation. For each scan rule, the regular expression pattern is base64-encoded to prevent pipe-delimiter collisions. Five output adapter files are emitted: two Zsh, two PowerShell, and one TypeScript snapshot.
FIG. 4 — Web portal architecture
Angular app shell with lazy-loaded feature routes. NavComponent, StatusComponent, and GlossaryComponent read from the TENANT_DOMAIN build-time constant (no HTTP fetch). The scan route mounts a React island via ReactBridgeService; the island calls POST /api/v1/scan/ at runtime.
FIG. 5 — Static analysis engine flow
ScanRequest with optional rule_ids, severity, category, and path filters rules from TenantDomain. For each rule: base64-decode the pattern field, compile as regex, traverse the filesystem applying scope globs and exclusions, collect ScanFinding records. Result aggregation returns a ScanResult with max_severity and clean status.
